# SIED SYSTEM V5 V0.4 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a buildable V0.4 foundation whose dashboard reflects the real local queue and whose read-only PPE adapter is verified against synthetic pages.

**Architecture:** Rust/Tauri remains the authority for SQLite state and summaries. React consumes typed commands and preserves the approved visual system. The PPE browser logic is split into pure contracts plus a Playwright adapter tested on local synthetic HTML before any live-session validation.

**Tech Stack:** Tauri 2, Rust 2021, rusqlite, React 19, TypeScript 5.8, Vite 6, Node test runner, Playwright, Microsoft Edge.

**Spec:** `docs/superpowers/specs/2026-11-13-sied-v04-foundation-design.md`

## Global Constraints

- Cost of services: R$ 0; free local dependencies only.
- Preserve the black/silver/glass visual identity and three-second splash.
- Never collect CPF, password, OTP, authenticator secrets, or another person's identity.
- Never automate Despachar, Assinar, Concluir, or another official write action.
- Never send real B.O. content to external providers.
- Use only synthetic data in automated browser tests.
- Stop safely on ambiguous DOM, duplicates, restrictions, or expired sessions.
- Do not deploy, publish, or initialize/push Git without explicit user direction.

## Review Focus

- Duplicate B.O. numbers must stop exact-row selection and create no browser action; covered in Task 4.
- Unknown/legacy SQLite status values must migrate without data loss; covered in Task 2.
- A session-expired/login page encountered mid-read must return `FALHA` and never continue; covered in Task 4.
- Restricted or missing tabs must be distinguished from genuinely empty data; covered in Task 4.
- Dashboard counts must not mix synthetic demo records with persisted queue records; covered in Task 3.
